# War Gaming

لعبة حرب جماعية بالفرق للهاتف، ثنائية الأبعاد — تدعم **اللعب أونلاين** مع
الأصدقاء عبر الإنترنت، و**اللعب المحلي عبر البلوتوث** بدون إنترنت. فريقان
(أحمر/أزرق)، حركة بعصا تحكم افتراضية، إطلاق نار، ونقاط حياة — يفوز الفريق
الذي يقضي على الفريق الآخر بالكامل.

## بنية المشروع

```
war-gaming/
├── server/    خادم Node.js (WebSocket) — المرجع الرسمي للعب الأونلاين
├── mobile/    تطبيق Flutter + Flame — الواجهة ومحرك اللعبة (android/ios جاهزان)
└── docs/      شرح تقني تفصيلي للبنية (ARCHITECTURE.md)
```

اقرأ `docs/ARCHITECTURE.md` لفهم كيف يعمل اللعب أونلاين والبلوتوث بنفس
البروتوكول، و`mobile/README.md` لخطوات تشغيل التطبيق فعليًا على جهاز.

## البدء السريع

### الخادم

```bash
cd server
npm install
npm test      # 13 اختبارًا وحدويًا لمنطق الغرف والتحقق من الإصابات
npm start     # يستمع على ws://localhost:8080
```

### تطبيق الهاتف (Flutter)

```bash
cd mobile
flutter pub get
flutter run
```

مجلدا `android/` و`ios/` جاهزان بالفعل مع أذونات البلوتوث/الموقع المطلوبة.
راجع `mobile/README.md` لكيفية الاتصال بالخادم من محاكٍ أو جهاز حقيقي.

## حالة المشروع بصراحة

هذه **نسخة أولى (MVP)** تعمل فعليًا وتم التحقق منها آليًا، وليست تطبيقًا
جاهزًا للنشر على المتاجر مباشرة:

- ✅ **الخادم**: منطق الغرف، توازن الفرق، الجاهزية، بدء اللعبة، التحقق من
  الإصابات — **13 اختبار Jest ناجح** + اختبار end-to-end عبر WebSocket حقيقي.
- ✅ **تطبيق الهاتف**: تم تثبيت Flutter SDK فعليًا في بيئة العمل والتحقق من
  المشروع بالكامل — **`flutter analyze`: لا توجد أي مشاكل**، و**`flutter
  test`: 6/6 اختبارات ناجحة** (منطق التحقق من الإصابات + اختبار واجهة يبني
  الشاشة الرئيسية فعليًا). مجلدا `android/` و`ios/` مُولَّدان ومُدرجان في
  المستودع مع أذونات Bluetooth/الموقع/الشبكة المحلية المطلوبة لـ
  `nearby_connections`.
- ✅ **CI**: `.github/workflows/ci.yml` يشغّل اختبارات الخادم والتطبيق تلقائيًا
  على كل push.
- ⚠️ **لم يُختبر بعد**: البناء الفعلي لملف APK/IPA (يحتاج Android SDK / Xcode
  غير متوفرين في بيئة الإنشاء)، واللعب الفعلي عبر بلوتوث بين جهازين حقيقيين
  (المحاكيات عادة لا تدعمه) — استدعاءات `nearby_connections` صحيحة من ناحية
  التحليل الساكن (تُستورد وتُستخدم بلا أخطاء) لكن سلوكها الفعلي في التقاء
  جهازين يحتاج اختبارًا ميدانيًا.
- ❌ **غير موجود بعد**: حسابات مستخدمين، حماية من الغش متقدمة، تحسين حركة
  الشبكة (interpolation/throttling)، دعم أكثر من فريقين، أصوات ورسومات
  احترافية، إعداد النشر الفعلي على Google Play / App Store (يتطلب حسابات
  مطوّر، توقيع التطبيق، ومراجعة كل متجر).

## خارطة طريق مقترحة

1. اختبار اللعب بين هاتفين حقيقيين (أونلاين ثم بلوتوث).
2. نشر الخادم على استضافة دائمة (Render / Fly.io / VPS) بدل `localhost`،
   وتحديث `kDefaultServerUrl` في `mobile/lib/screens/lobby_screen.dart`.
3. تحسين تجربة الشبكة: تقليل تردد `player_state`، إضافة تنعيم للحركة.
4. إعداد أيقونة/اسم التطبيق، توقيعه (keystore لأندرويد، شهادة لـ iOS)،
   وإرساله لمراجعة المتاجر.
