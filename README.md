# War Gaming

لعبة حرب جماعية بالفرق للهاتف، ثنائية الأبعاد — تدعم **اللعب أونلاين** مع
الأصدقاء عبر الإنترنت، و**اللعب المحلي عبر البلوتوث** بدون إنترنت. فريقان
(أحمر/أزرق)، حركة بعصا تحكم افتراضية، إطلاق نار، ونقاط حياة — يفوز الفريق
الذي يقضي على الفريق الآخر بالكامل.

## بنية المشروع

```
war-gaming/
├── server/    خادم Node.js (WebSocket) — المرجع الرسمي للعب الأونلاين
├── mobile/    تطبيق Flutter + Flame — الواجهة ومحرك اللعبة
└── docs/      شرح تقني تفصيلي للبنية (ARCHITECTURE.md)
```

اقرأ `docs/ARCHITECTURE.md` لفهم كيف يعمل اللعب أونلاين والبلوتوث بنفس
البروتوكول، و`mobile/README.md` لخطوات تشغيل التطبيق فعليًا.

## البدء السريع

### الخادم (مُختبر ويعمل)

```bash
cd server
npm install
npm test      # 13 اختبارًا وحدويًا لمنطق الغرف والتحقق من الإصابات
npm start     # يستمع على ws://localhost:8080
```

### تطبيق الهاتف (Flutter — يحتاج إعدادًا محليًا)

```bash
cd mobile
flutter create .   # يولّد android/ios/web حول lib/ الجاهز
flutter pub get
flutter run
```

راجع `mobile/README.md` للأذونات المطلوبة (بلوتوث وموقع) وكيفية الاتصال
بالخادم من محاكٍ أو جهاز حقيقي.

## حالة المشروع بصراحة

هذه **نسخة أولى (MVP)** قابلة للعمل من ناحية التصميم والمنطق، وليست تطبيقًا
جاهزًا للنشر على المتاجر مباشرة:

- ✅ **الخادم**: منطق الغرف، توازن الفرق، الجاهزية، بدء اللعبة، التحقق من
  الإصابات — كل ذلك مكتوب **ومُختبر فعليًا** (13 اختبار Jest + اختبار
  end-to-end عبر WebSocket حقيقي).
- ⚠️ **تطبيق الهاتف**: مكتوب بالكامل (الشاشات، محرك اللعبة عبر Flame، عصا
  التحكم، الاتصال أونلاين وبلوتوث) لكن **لم يُجمَّع فعليًا** لعدم توفر
  Flutter SDK في بيئة الإنشاء. شغّل `flutter analyze` و`flutter test` بعد
  `flutter pub get` لالتقاط أي خطأ تجميع طفيف.
- ⚠️ **البلوتوث تحديدًا**: يعتمد على حزمة `nearby_connections`؛ التوقيعات
  البرمجية المستخدمة تعكس التوثيق الرسمي للحزمة لكنها غير مُختبرة بالتجميع.
  اختبر على جهازين حقيقيين — المحاكيات عادة لا تدعم بلوتوث.
- ❌ **غير موجود بعد**: حسابات مستخدمين، حماية من الغش متقدمة، تحسين حركة
  الشبكة (interpolation/throttling)، دعم أكثر من فريقين، أصوات ورسومات
  احترافية، إعداد النشر الفعلي على Google Play / App Store (يتطلب حسابات
  مطوّر، توقيع التطبيق، ومراجعة كل متجر).

## خارطة طريق مقترحة

1. تشغيل `flutter create .` وإصلاح أي أخطاء تجميع.
2. اختبار اللعب بين هاتفين حقيقيين (أونلاين ثم بلوتوث).
3. نشر الخادم على استضافة دائمة (Render / Fly.io / VPS) بدل `localhost`.
4. تحسين تجربة الشبكة: تقليل تردد `player_state`، إضافة تنعيم للحركة.
5. إعداد أيقونة/اسم التطبيق، توقيعه، وإرساله لمراجعة المتاجر.
